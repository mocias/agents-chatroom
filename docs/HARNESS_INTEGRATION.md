# Harness 接入与验收指南

本指南供社区实现新后端时使用，当前为接入约定，不表示已经实现可动态加载的插件 API。候选与优先级见 [路线图](../ROADMAP.md)，提交方式见 [贡献指南](../CONTRIBUTING.md)。

## 先确认接入对象

记录应用名称、厂商/维护者、官方仓库/接口文档、发布版本、许可证/分发限制和支持平台。区分 harness、模型提供商、桌面宿主与 CLI。例如 Qwen Code 不是 Qoder，CodeBuddy CLI 不是现有 WorkBuddy 桌面 supervisor，Kimi Code CLI 也不能直接照搬已归档的旧 CLI 实现。

优先级：官方 ACP/SDK/结构化控制接口，其次有明确维护者和版本的适配桥接。MCP 支持只表示可以接工具，不证明宿主可创建和控制 Agent 会话。CLI 可启动也不表示能安全解析终端输出、恢复会话或逐工具授权。

## 建议实现步骤

1. **先做一个明确入口**：核对用户手动选定的本地程序，解析版本与协议；无许可不做自动扫描。Windows 使用原生 exe 或已验证的 Node 入口，不通过拼接 shell 字符串执行含空格/特殊字符的路径。
2. **完成协议生命周期**：启动、握手、必要认证、独立会话、流式文本、取消与退出清理。版本/能力协商决定支持范围，不能假定所有 ACP 实现的方法、扩展或 MCP 传输一致。
3. **接入目录和配置**：检查 `lib/harnesses.cjs`、`standalone/discovery.cjs`、`standalone/models.cjs` 与 `standalone/server.cjs` 的注册/校验/启动路径。新后端若需修改多个清单，应在 PR 说明；统一注册是后续计划，当前不能假定一个外部 JSON 就能接通。
4. **接入房间与界面**：协议适配复用现有 pool 行为，与 `lib/room.cjs` 核对 `start/stop`、模型与能力查询、`openThread/getThread/closeThread`、`runTurn`、`interrupt` 等实际调用；检查 `standalone/public/app.js` 中标签和全部/单聊/群聊展示，不遗漏新 harness 名称。
5. **按能力开放高级功能**：单独验证 MCP、图片、恢复、推理档位和桌面登记。未支持的能力要明确返回不可用；先完成单聊与群聊，再谈投票或原生历史导入。
6. **交付证据**：完善回归、更新 README 适配矩阵，提交脱敏结果；由维护者确认状态后更新路线图，不提前勾选为完成。

## 必须保留的行为

| 项目 | 验收要求 |
| --- | --- |
| 身份/会话 | 同一 Agent 保持稳定工作区，不同群/单聊使用不同原生会话；两个房间不会串历史、角色或配置 |
| 模型 | 用户选择的模型严格应用；目录、账号权益、实际可调用是三个不同检查，不静默切换到其他模型 |
| 能力 | 只暴露真实支持的模型/推理/附件/恢复选项；未知信息标为未知，不填虚构默认值 |
| 权限 | 保留原有文件与执行批准；以真实工具标识和绑定检查，不能用显示标题/模型自报身份批准工具 |
| 发现/登录 | 手动模式不扫描；复用受支持的本地登录路径，不读取/复制凭据到仓库，不擅自修改全局 MCP 配置 |
| 请求状态 | 分开报告发送前拒绝、已接受、生成中和结果未知；对已派发但未知的请求不自动重放 |
| 生命周期 | 取消、后端退出、超时、SSE 断开和程序关闭可收尾；临时查询会话不会留下独立后台 worker |
| Windows | 空格、中文、不同盘符、exe/cmd shim、路径大小写与 ASAR/Electron Node 运行方式按实际场景验证 |
| 数据 | 升级/删除/卸载不会越界移除工作区；已有目录和聊天不被测试覆盖，测试使用隔离路径 |

### MCP 与投票另行验收

Room 当前投票工具为 `poll_create`、`poll_list`、`poll_get`、`poll_vote`、`poll_abstain`、`poll_close`、`poll_cancel`。新增 harness 需要证明它实际获得了绑定本房间/本 Agent 的 MCP 连接，并完成工具调用，而非仅在初始化参数里出现服务器配置。

必须覆盖：发起者也投票、重复调用去重、跨房间与冒充身份拒绝、忙碌与取消、截止/重启、匿名截止前隐藏选票和正文/工具参数、完成后只返回授权汇总。内部磁盘或后端原生记录不提供加密匿名保证。

只支持聊天而不支持 MCP 的适配可以明确提交有限能力版本；不能声称因此支持群聊投票。原生工作区登记与原生聊天历史恢复也要分别描述，不能通过写入私有数据库伪造成功。

## 最小测试矩阵

| 层次 | 需要的结果 | 不能据此宣称 |
| --- | --- | --- |
| 模拟协议 / 自动回归 | 请求形状、配置映射、权限拒绝、流式/取消/错误、两个房间隔离与清理 | 真实账号可用、模型回复成功 |
| 显式真实单聊 | 记录 OS、harness 版本、模型、一次短回复、流式/停止和清理 | 所有模型、所有平台可用 |
| 显式真实群聊 | 两位成员、独立 session ID、点名/私聊和消息可见范围 | MCP 投票可用或原生桌面已同步 |
| MCP / 投票 | 七工具授权、独立投票与结算、匿名可见范围 | 仅凭 MCP 配置推断真实工具可调用 |
| 打包程序 | 最终 EXE/ASAR 启动、桥接可读、源码匹配与隔离数据保留 | 用户已安装或已完成安装器验收 |

PR 提供版本、命令、结果、失败/跳过原因、脱敏截图或短报告即可；不要上传原始个人会话、账户目录、令牌和整份运行时。没有账户的贡献者可明确标记未执行真实检查，由具备环境的维护者/贡献者后续补齐。
