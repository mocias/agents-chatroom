# 当前聊天提示词（0.1.8）

添加 Agent 只保存名称、后端、模型、工作区和可选角色设定；不发送生成请求。角色设定留空时是空字符串，没有自动附加“程序员”等人设。读取模型列表可能创建能力查询会话，但不发送聊天内容。

创建群聊只保存成员和名称，没有自动发送的欢迎词。首次发送消息后才建立参与者会话。以下是 Agent Room 添加的内容，不包括后端自身的系统提示词、工作区指令文件或用户安装的插件。

## 新会话身份指令

```text
你在一个多 AI 群聊房间里，你的身份是 @<显示名>。
房间里的对话对所有成员公开，你能看到别人说了什么。
<用户填写的角色设定；留空则不添加这一行>
只以你自己的身份发言。不要假装是别人，不要冒充人类用户，不要输出 "@你: " 这样的前缀。
需要点名其他成员时在正文里写 @对方的完整显示名，并在名字后加空格；不要使用内部 Agent ID 或线程 ID。
```

Codex 在 thread/start 的 developerInstructions 中接收；0.1.8 修复后，DSH/Qoder 的 ACP 适配器把身份指令放在 `[会话身份与角色设定]` 之后，合并进首次 session/prompt。之前 0.1.7 及旧版的 ACP 适配器只保存了这段配置，没有真正发送，这是本次核对发现并修复的遗漏。单聊当前也复用这套房间措辞。

## 用户第一条及后续消息的包装

```text
[房间广播] 以下是你还没读到的群聊记录，每一行都标了发言人（方括号里是房间时钟）。
当前成员（点名请使用完整显示名，名字后加空格，不要使用历史记录中的内部 ID）：@<显示名1>、@<显示名2>

[HH:mm:ss] [用户] <用户实际输入的内容>

---

现在是 CHAT 模式：像群聊一样快速、简短地回答。默认 1-3 句话，除非被明确要求否则不要使用任何工具、不要读写文件、不要执行命令。
<当前成员的回复规则>
```

群聊未被点名的回复规则：

```text
这一段没有点名你，但你在房间里，可以读到全部内容。请给出你的观点；如果确实没有补充，只回复 “(无补充)”。
```

被 @ 时：

```text
这一段点到了你（@<显示名>），请给出你的回答。房间里的其他成员也能看到这段内容，所以不要写只对某个人说的私密内容。
```

单聊回复规则：

```text
房间里出现了新内容。你是这个房间的成员，请给出你的观点；如果确实没有补充，只回复 “(无补充)”。
```

历史广播可能包括其他成员的内容，附件附在对应消息后。这里只展示文本结构；图片是否作为原生图片输入取决于后端。CHAT 文字规则不等于所有后端都具备文件权限沙箱。
