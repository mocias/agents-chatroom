# Agents Chatroom

本地多 Agent 聊天应用，基于 [dsh-agent-room](https://github.com/mocias/dsh-agent-room) 开发。支持 Codex、DSH、Qoder 单聊与群聊，支持 Claude Code 终端版和 Claude 桌面 Gateway API 配置接入，并提供 WorkBuddy 国内版与 WorkBuddy AI 国际版的实验性本机接入。提供浏览器和 Windows 桌面版。当前版本 **0.1.22**。

- 微信式联系人和群聊界面，目前只开放 CHAT；支持重命名、Agent 置顶和独立滚动。
- 输入 @ 选择当前成员或“所有人”，流式回复增量渲染。
- 真实模型列表、固定 Agent 模型、按会话调整推理档位（取决于后端能力）。
- Agent 独立工作区，桌面版默认 `安装目录/agents/后端名称/Agent名称`，浏览器版默认 `项目目录/agents/...`；旧 Agent 保持原路径。
- 删除 Agent 时选择保留或删除工作区，默认保留；共享目录和危险路径禁止删除。
- 扫描前告知，可拒绝扫描并手动配置。
- 文件、图片附件及外观设置，数据保存在本机。

## 启动

需要 Node.js 22+；浏览器版没有额外运行依赖：

```sh
npm start
```

打开 http://127.0.0.1:4318 。后端需分别安装并登录。

```sh
npm ci
npm test
npm run desktop
npm run desktop:dist
```

桌面构建面向 Windows x64，产物在 `dist/`。安装包未签名，尚无自动升级；用户数据及构建产物不随源码上传。首次安装开发依赖需要下载 Electron。

## Claude Code 接入

在“后端管理”选择 Claude Code。终端版可指定 claude.exe、npm claude.cmd 或 CLI JavaScript 入口；桌面版可选择已配置 Gateway API 的 Claude.exe，桥接会使用该桌面下载的 Code 运行程序及当前用户的 API 配置。

桌面 API 密钥仅由本机桥接进程在内存中读取并传给其子进程，不写入 Room 的后端配置、聊天记录或测试报告。每次新会话读取当前已应用的桌面配置和缓存模型映射，避免终端别名意外指向桌面未使用的新模型。尚未实现 Claude 桌面任务列表同步，也未验证第一方桌面账号登录复用。

接入保留 0.1.17 的身份、私聊、闹钟及群管理逻辑；目前只开放文本 CHAT，禁用工具、hooks 和额外 MCP，未开放推理档位。

**验证：80 项离线检查通过；已安装的 0.1.19 使用桌面 Code 2.1.299 + Gateway API + Haiku，真实返回 CLAUDE_ROOM_OK。本轮仅发送一条测试消息；未做多成员、多模型真实验收。** 详情见 HANDOFF。

检查脚本默认只做初始化及模型选择，不发送生成请求：

    node scripts/check-live-claude.cjs "Claude 程序完整路径" --model=haiku

加 --chat 才发送一条短回复请求，并使用账号额度；验证脚本关闭思考，输出上限 32 tokens。普通用户聊天不受这个测试上限限制。

## 代理与安装路径

默认沿用应用进程的代理环境；没有配置时不强制设置代理端口。TUN 网络由系统路由处理。需要单独指定时，在“后端管理 → 仅此后端使用的代理”填写实际 HTTP/SOCKS 地址，留空恢复继承；只影响 Room 启动的该后端，不修改系统代理或 Dot 设置。WorkBuddy 使用其桌面应用的网络配置。

后端程序、Room 数据和 Agent 工作区可以位于不同磁盘。新联系人无需预先创建旧共享工作区；进程使用有效目录启动，会话继续使用各自的工作区。跨盘真实 Codex 验证及尚未覆盖的代理模式见 HANDOFF。

## 自定义数据目录（自动迁移，0.1.12）

在“后端管理 → 数据目录与自动迁移”选择空文件夹，点击“迁移并重启”。应用在退出后自动复制、校验，再启用新目录；浏览器版需手动重启服务。旧版已经保存的待迁移路径也会自动执行。不覆盖目标已有的不同内容，失败时继续使用旧目录，旧数据始终保留。

数据目录内部的工作区一并复制并更新路径；外部工作区不变。迁移后重建后端会话并回放 Room 历史，避免复用绑定旧工作区的会话。目录含符号链接时会拒绝迁移并说明原因。

## 增量升级（0.1.12 起）

无需卸载。下载匹配当前版本的增量 ZIP，解压到程序目录之外，双击 Update.cmd，输入安装目录（例如 D:\Agent Room）。更新器校验旧文件和补丁，重建并校验新文件，关闭应用后替换，再启动；聊天数据、工作区和自选目录保留。失败会回滚已替换文件，备份保存在安装目录的 .update-backup-* 下。仅支持 Windows 本地目录，不支持链接路径。

这是手动下载运行的增量更新包，暂不包含应用内联网检查更新。版本不匹配会拒绝更新，不能跳过增量包指定的基准版本；首次安装仍使用完整安装包。

生成发行补丁：

```powershell
node scripts/build-incremental.cjs <旧版目录> dist/win-unpacked <补丁输出目录> <旧版本> <新版本>
```

## 群聊私聊与多消息（源码第一版）

普通文字和 `@成员` 公开；消息开头 `#完整成员名 内容` 私聊，仅双方 Agent 接收，用户可查看全部。独占一行的 `---` 将一次回复拆成多个独立气泡；代码块中的分隔符不拆分。输入 `#` 可补全群成员。私聊气泡使用紫色并显示发送者、接收者与“用户可见”。

模型回复结束后统一校验并投递，生成期间为用户预览。未知私聊对象拒绝整批；用户内容恢复草稿。每块独立判断范围，多块附件仅属于第一块。接收方看到的正文保留 `#接收者`，并明确标注私聊；回复私聊仍需写 `#原发送者`。

完整规则见 [agent-room-skill.md](agent-room-skill.md)，首次后端会话注入，重建时重新发送；后续轮次只加简短提醒。技能修改需重启服务。源码更新不等于已安装桌面版更新。


## 闹钟工具（0.1.11）

Agent 或用户在单独消息块发送：

```text
/alarm 10m #审查员 检查任务是否完成
---
/alarm 2026-10-17T18:00:00+08:00 @所有人 汇总今日进展
```

`s/m/h/d` 表示秒/分钟/小时/天；绝对时间须带日期、秒与时区。`#成员` 私密提醒，`@成员` 公开点名，`@所有人` 全体提醒，`#用户` 仅提醒人类。系统确认后才算创建成功；界面“闹钟”入口可查看、取消。

消息统一展示为 `#发送者：#接收者 内容` 或 `@发送者：@接收者 内容`，发送者由应用确认。到期消息如 `#系统：#审查员 当前时间为：2026-10-17 18:00:00 (Asia/Shanghai)，检查任务是否完成`。原有简写继续支持；公开且未点名的消息为 `@发送者：内容`。

闹钟保存在数据目录的 alarms.json；一次性触发，最多提前 366 天，每个群最多 100 个待触发项。应用需运行才能准点发出；退出、断电或休眠期间到期的提醒会在恢复运行后补发。提醒事件按 ID 去重，后端模型不可用不影响已保存的提醒记录。此工具由独立应用/桌面宿主管理，原 DSH 插件宿主尚未接入调度器。

## 群聊管理（0.1.13）

在左侧群聊上右键，或打开群聊后点击右上角“⋯”，可以重命名、置顶/取消置顶、删除群聊。置顶跨重启保留，同类置顶状态内按最近消息排序。

删除需要确认；仅移除群聊入口，关闭其后端会话并取消待触发闹钟。Agent 联系人、其他会话、工作区、本地历史/附件文件及原后端对话保留，不做文件清理。群聊正在回复或闹钟正在投递时，请等待结束后再删除。

WorkBuddy 模型列表读取已验证运行版本所用配置目录中的在线目录快照，遵循桌面 cli 角色的模型顺序，不再使用安装包静态模型补全。添加 Agent 时或点击“重新读取模型”会重新读取，并显示快照时间；这不会主动触发 WorkBuddy 云端刷新。多个账号缓存无法判定、缺失或格式不兼容时仅显示原生选项并提示。该目录不代表套餐授权，自定义模型配置与桌面的灰显/套餐提示尚未同步。
